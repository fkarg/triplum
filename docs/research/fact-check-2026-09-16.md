## Notes and gotchas

**Naming collisions to guard against**
- **Two unrelated papers are both called "GraphRAG-Bench."** arXiv **2506.05690** (XMU-DeepLIT / PolyU, ICLR 2026, MIT, repo `GraphRAG-Bench/GraphRAG-Benchmark`, HF `GraphRAG-Bench/GraphRAG-Bench`) vs arXiv **2506.02404** (PolyU + Tencent YouTu, unpublished preprint, repo `jeremycp3/GraphRAG-Bench`, no license). Only Xiao Huang overlaps between author lists. This is a live citation hazard.
- **`rudof`** on crates.io and PyPI is a stale 2024 0.1.12 artifact of the old `weso/shapes-rs` project. The live packages are `rudof_lib`/`rudof_cli` (Rust) and **`pyrudof`** (Python), all 0.3.21.
- **`lbug`** is the Rust crate; **`ladybug`** is the Python package. They are not interchangeable.

**Licensing risk — three projects have no license at all**
- `JayLZhou/GraphRAG` (DIGIMON), `stair-lab/kg-gen`, and `jeremycp3/GraphRAG-Bench` all have **no LICENSE file**. Under default copyright that means *all rights reserved* — no grant to use, modify or redistribute. kg-gen's `pyproject.toml` says MIT, which is evidence of intent but is not a license file; DIGIMON has nothing at all.

**Staleness flags**
- **DIGIMON**: last commit 2025-07-01 — ~14 months stale.
- **kg-gen**: last PyPI release 2025-09-30, last push 2026-03-24.
- **petgraph**: 0.8.3 from 2025-09-30, no 0.9.
- **`llm` (graniet)**: 1.3.8 from 2026-04-19 — the least active of the four Rust LLM clients.
- **`ort`**: still release-candidate only (2.0.0-rc.13); no stable 2.0.
- **`sqlite-vec`**: still pre-1.0, stable line at 0.1.9.
- **`ragas`**: 0.4.3 from 2026-01-13, repo last push 2026-02-24 — notably quiet for a 15.7k-star project.

**Ecosystem moves worth knowing**
- **Kùzu → LadybugDB.** `kuzudb/kuzu` is archived (final push 2025-10-10); LadybugDB is the direct continuation, same MIT license with the Kùzu Inc. copyright carried forward. Downstream consequence: **Graphiti has deprecated its Kuzu backend** and will remove it.
- **PyO3 free-threading is now opt-out** as of 0.28.0 (2026-02-01); 3.13t support was dropped in 0.29.0, 3.14t+ is the supported free-threaded target.
- **OpenAlex's polite pool and `mailto=` parameter no longer exist.** Any code still passing `mailto` for polite-pool treatment is dead code. The current model is a daily dollar budget ($0.10/day keyless, $1/day with a free key).
- **Semantic Scholar with an API key is *slower* than without** for burst traffic: 1 RPS per key vs a 1000 RPS pool shared across all anonymous users. The key buys reliability, not throughput.
- **DuckPGQ builds lag DuckDB releases badly.** There is currently no DuckPGQ build for DuckDB 1.5.5 (the current stable). Pin DuckDB 1.5.4, or 1.4.4 on the LTS line, if DuckPGQ is required. CDN probe (2026-09-16) showed builds present for 1.2.0, 1.3.2, 1.4.1, 1.4.3, 1.4.4, 1.5.0, 1.5.1, 1.5.4 and absent for 1.3.0, 1.4.0, 1.4.2, 1.5.2, 1.5.3, 1.5.5.
- **DuckDB `vss` is still experimental** and persistent HNSW indexes are explicitly not recommended for production (WAL recovery for custom indexes is unimplemented). The `vss_join`/`vss_match` macros are brute-force and do not use the index.
- **Text2KGBench-LettrIA has no public artifact** — "available upon request to the authors." Do not link a repo or dataset for it.
- **tantivy-py 0.26.2 was released on GitHub today (2026-09-16) but PyPI still serves 0.26.0.** Expect a short lag.
