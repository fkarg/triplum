# Plan: stages, provenance and replicates

Derived from [`../specs/2026-09-17-stages.md`](../specs/2026-09-17-stages.md). Snapshot
2026-09-17. Four commits on local main, each green under the pre-commit gate, the offline test
suite and the strict docs build. The fixture pipelines and the extraction fixture tests are the
regression harness throughout: their numbers do not move.

## Commit 1: the `triplum.stage` package, additive

Nothing existing changes behaviour. One package with one responsibility per module, so each is
testable alone:

1. `stage/fingerprint.py`: what code is. `is_first_party(filename)` by path against
   `sysconfig` `purelib`, `platlib`, `stdlib`, `platstdlib` (the working tree's `.venv` is under
   the repository, so the check is on the site paths, not on a root prefix). `outer(code)`
   walks a code object's qualified name up to the first `<locals>` and resolves the containing
   function or method in its module. `source_hash(fn)`: `inspect.getsource`, dedent, parse,
   docstrings stripped from every `Module`, `ClassDef`, `FunctionDef`, `AsyncFunctionDef`
   body, `ast.dump` without attributes, sha256; falls back to the bytecode and constants of the
   code object when `OSError` (no source), marked `"bytecode:"`. `constants(fn)`: the global
   names in `co_names` (recursing into nested code objects) that resolve in `fn.__globals__`
   to plain data (`str`, `int`, `float`, `bool`, `bytes`, `None`, and `tuple`, `frozenset`,
   `list`, `dict` of plain data), as canonical JSON. `distribution(module_name)` through
   `importlib.metadata.packages_distributions`, version whole. `Manifest` (pydantic, frozen):
   `functions: dict[str, str]` (module:qualname to hash), `constants: dict[str, str]`
   (module:name to canonical value), `distributions: dict[str, str]`, `fixed: dict[str, str]`
   (the Rust extension's file hash, the migrations file hash); `code()` is its content key.
   `build(codes: set[CodeType]) -> Manifest`. `validate(manifest) -> bool`: resolve every
   function entry through `importlib.import_module` and attribute walking, unwrapping
   `functools.wraps` decorators, `property.fget`, `staticmethod` and `classmethod`
   `__func__`; rehash; any unresolvable or differing entry is `False`; constants and
   distributions compared the same way.
2. `stage/trace.py`: what code ran. A process-wide monitor on tool id 3 named `triplum`,
   `PY_START` only, callback records the code object into every active recording and returns
   `DISABLE`. `Recording` is a context manager: enters by `restart_events()` and pushing a set
   onto a stack, exits by popping; nested recordings both receive every entry. `enabled()`
   lazily claims the tool id once per process. A code object whose file is not first-party is
   recorded as its module name only, for the distribution list.
3. `stage/identity.py`: what a stage is asked. `identity(value) -> Any` implements the
   argument table of the spec: `Dataset`/`IterableDataset` by `fingerprint()`, `Artifact` by
   `(key, code)`, a store by `identity()` (added to the store protocol: corpus and graph
   identities from meta), pydantic by `model_dump(mode="json")`, frozen dataclass by `asdict`,
   an adapter by `spec.hash()` or, for an LLM, `(adapter, model)`, plain data by value;
   `TypeError` otherwise. Every non-plain value is paired with its type's module and
   qualified name. `keys(name, bound_args, seed) -> (structural, execution)`;
   `seeded(bound_args)` is true when a `seed` parameter exists or any argument has
   `seed_sensitive` true. `derive(*parts) -> int` is `content_key` truncated to 64 bits.
4. `stage/artifacts.py`: where outputs live. `Artifact` (pydantic): `stage`, `key`, `code`,
   `kind`, `path`, `content_hash`, `rows`, `bytes`. `publish_frame`, `publish_records`,
   `StreamWriter` (numbered parquet batches, `complete.json` last with hash, rows, sizes;
   temporary directory, one `os.replace` to publish; an existing target wins and the temporary
   directory is removed), `read(artifact)` returning a frame, a record list, or an
   `IterableDataset` that yields batch by batch with `fingerprint()` = `(key, code)`.
   `complete(path) -> Artifact | None` checks the record and the file sizes.
5. `stage/run.py`: the context. `Run` (run store, cache root, replicate seed, run id,
   replicate) in a `ContextVar`; `current()`; `run(...)` context manager.
6. `stage/stage.py`: the wrapper. `stage(fn)` returns a `Stage` with `fn`, `name`,
   `__call__`. Without a current `Run`, `__call__` is `fn`. With one: bind arguments, keys,
   derived seed injected into a `seed` parameter when present, lookup through
   `RunStore.artifacts(key)` filtered by `validate` and `complete`; on a hit, record the
   invocation as fetched and return `read(artifact)`; on a miss, start the invocation, record
   inputs, run under a `Recording`, publish by return type (a generator or `IterableDataset`
   is wrapped so the recording stays open through every pull and the writer completes on
   exhaustion; a store-effect stage returns `None` and its lookup asked the store through
   `store.effect_complete(key)` before anything else), build the manifest, insert the artifact
   row, finish the invocation. An exception marks the invocation `failed` with the message,
   removes the temporary directory and propagates.
7. `bench/runstore.py`: the provenance tables from the spec (`artifacts`, `invocations`,
   `invocation_inputs`, `manifests`) beside the existing ones; `runs` gains `experiment_id`
   and `replicate`. Methods: `artifacts(key)`, `add_artifact_row`, `start_invocation`,
   `finish_invocation`, `add_invocation_inputs`, `manifest(code)`, `put_manifest`,
   `invocations(run_id)`, `lineage(key, code)`. The old `run_artifacts` table and
   `add_artifact` stay until commit 3.
8. `store/protocol.py` and `store/sqlite/store.py`: `identity()` and the `effects` table
   (`key TEXT PRIMARY KEY, stage, started_us, completed_us`) with `begin_effect`,
   `complete_effect`, `effect_complete`; this is the store's ingestion log in its first form,
   layer 1 refines it.
9. Tests, all offline: `tests/test_stage_fingerprint.py` (a comment, a docstring and a
   reformat leave the hash unchanged; a default, a decorator and a body change change it; a
   module constant is captured and a module-level object is not; first-party by path treats
   `tests/` and an editable module as source and `polars` as a distribution; `validate`
   resolves a decorated method, a property, a static and a class method, a local function's
   outer, and fails closed on a monkeypatched function and on an unresolvable entry).
   `tests/test_stage_trace.py` (a stage that dispatches through a method on its argument
   records the method; a generator body's helper is recorded when consumed through the
   wrapper and not when the plain generator is returned; nested recordings both see an
   inner entry; the callback disables itself, asserted by a call counter). `tests/test_stage.py`
   (second call fetches with zero executions of `fn`; editing the source of a helper on disk
   and reloading reruns only the stage that used it; a store subclass reruns the stages that
   took the store; a stream artifact completes on exhaustion, a consumer that stops half way
   leaves no readable artifact, a rerun streams from parquet; an opaque argument is a
   `TypeError`; no context runs `fn` directly; a seeded stage gets a derived seed and a
   stage with a seed-sensitive adapter argument is seeded without a parameter).
   `tests/test_runstore.py` gains the provenance rows and a lineage walk.

## Commit 2: seeds, adapters and configs

1. `seed_sensitive` on every adapter: `CachedLLM`, `OpenAICompatLLM`, `CliLLM` true;
   `FakeLLM` false with a `perturb` flag that makes its answer depend on `params.seed`, for
   the acceptance test; embedders, rerankers and extractors false. The LLM call key already
   carries the seed through `GenParams`; the wrapper passes the derived seed into the
   `GenParams` it builds, so nothing changes in `request_hash`. `honours_seed` recorded on
   the run stays as it is (R4).
2. `bench/config.py`: `EmbedderConfig`, `LLMConfig`, `RerankerConfig`, `PipelineConfig`,
   `ExtractorConfig`, `ExtractConfig`, `RunConfig` become frozen pydantic models;
   `to_json`/`from_json` are `model_dump_json`/`model_validate_json`; `_from_dict`,
   `_NESTED`, `_TUPLES` go; `hash()` unchanged in value where possible (the dump is the same
   dict, so it is). `RunConfig.replicates: int = 1`. `ResolverSpec` and `ExtractorSpec` stay
   dataclasses (identity table accepts both). `tests/test_config.py` round-trips every config
   and asserts the hashes of the fixture configs are unchanged against the values recorded
   in the committed run store fixture if one exists, else against literals captured before the
   change.
3. `bench/cli.py`: `--replicates N` on `bench` and `rerun`; `replace(cfg, ...)` becomes
   `cfg.model_copy(update=...)`.

## Commit 3: the runner on stages, replicates, the report

1. `bench/stages.py` (new): the pipeline as stages over the existing functions, one per
   existing event: `ingest(store, corpus)` and `embed(store, chunks, embedder)` and
   `graph(store, extraction)` as store-effect stages; `materialise(benchmark)` with a
   `records` artifact (R7); `retrieve(qa, store, pipeline_cfg, embedder, reranker, viewer)`
   returning the hits frame; `read(question, hits, store, reader, viewer, seed)` per question
   and `judge(question, answer, judge_llm, seed)` per question, seeded; `extract(chunks,
   extractor)` with a `frame` artifact of spans and claims, `ground(...)` and `resolve(...)`
   as separate stages (R9, R10); `score(...)`. Every stage takes what it uses as arguments
   and reads no module global but constants.
2. `bench/runner.py`: `run_benchmark` composes those stages under a `Run` context. Identity
   before any read: `corpus_hash` and `questions_hash` from `Benchmark` fingerprints, `n` from
   the config, no `materialize` before `find_run` (R6, gap 8). `find_run` takes the identity
   without `code_hash` and validates every invocation's manifest of each candidate; the run's
   `code_hash` becomes the content key of its invocations' code fingerprints, recorded after.
   `store` artifact by identity (R14). `run_experiment(cfg) -> list[str]` loops replicates
   with `derive(cfg.seed, r)`; `run_benchmark` is `run_experiment(...)[0]` for
   `replicates == 1`. `bench/fingerprint.py` and `tests/test_fingerprint.py` are deleted;
   `code_version()` stays for bookkeeping.
3. `bench/report.py`: `variance(rs, experiment_id) -> tuple[pl.DataFrame, pl.DataFrame]`, the
   per-invocation table (stage, structural key, inputs agree, outputs agree, verdict,
   fetched) and the metric table (mean, std over replicates). `bench_view.print_variance`.
   The CLI prints both after a run with `replicates > 1`; `bench variance <run_id>` shows
   them for a stored experiment.
4. `docs/benchmarking.md` identity table and `IDENTITY_FIELDS` become one list (R15);
   `inspect` and `diff` show per-stage code changes from the invocations.
5. Tests: `tests/test_runner_stages.py` (second run fetches every stage and reads no dataset,
   asserted with a source whose `__iter__` raises after the first run; three replicates with
   the fake reader are all deterministic; with `perturb` the read stage adds variance,
   retrieval is fetched, the metric std is non-zero; a run with `replicates=3` returns three
   ids and replicate 0 is what `find_run` returns). Existing runner tests updated for the
   pydantic configs. `tests/integration/test_pipelines_fixture.py` unchanged in expectations.
